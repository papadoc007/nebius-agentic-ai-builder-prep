1. Running inference on Token Factory

~20%
  • The API is OpenAI-compatible: use the openai SDK with base_url="https://api.tokenfactory.nebius.com/v1/" and a key from NEBIUS_API_KEY.
  • stream=True returns chunks with delta.content. It improves time to first token (TTFT), not total time.
  • Playground: model cards show price per 1M tokens, tokens/sec, and MMLU as "Quality". Compare runs two setups side by side, View code exports the setup as code, Save preset stores it. The Playground exposes the common parameters; the API exposes the full vLLM parameter set.
  • Base vs Fast: identical outputs. Fast (append -fast to the model name) uses speculative decoding and smaller batches, so lower latency at a higher price per token. Fast for chat and interactive agents, Base for high-volume background work.
  • Model choice: start small and cheap, move up only when quality is not good enough.
  • temperature low (0-0.2) for extraction, classification and code; high (0.7-1) for creative work. Tune temperature or top_p, not both. max_tokens caps length and cost, seed helps reproducibility.
  • Batch: for high-volume work that does not need an immediate answer, never for live chat. Flow: files.create(purpose="batch"), then batches.create(..., endpoint="/v1/chat/completions", completion_window="24h"), results in output_file_id. Batch has significantly higher rate limits. (A 50% discount appears only in third-party sources, not in the official docs.)
Sources: Inference overview, Playground, batch.ipynb

2. Building Agentic AI

~35%
The heaviest domain. One test-taker wrote that most questions are production scenarios (symptom, constraint, decision) with very few definitions, stressing Tavily, tool_choice, the tool loop, structured output, and choosing between fine-tuning, RAG and tools. Source
  • Structured output: response_format of type json_schema enforces your schema (strict: true, additionalProperties: false). json_object only guarantees valid JSON, with no fixed fields. Handle message.refusal and validate in code (Pydantic).
  • Agent loop: the model decides, calls a tool, gets the result, continues. The loop ends when a response comes back without tool_calls. A tool result goes back with role: "tool" and a matching tool_call_id. The Responses API has max_tool_calls and tool_choice. Always cap the number of steps.
  • Memory: short-term = conversation history in the context window (trim or summarize). Long-term = external store (vector DB) with retrieval by relevance.
  • Tavily Search: search_depth = basic (default), fast, ultra-fast (1 credit) or advanced (2 credits, most relevant). topic = general / news / finance. max_results 0-20. time_range (day/week/month/year). include_domains in the default restrict mode is a hard filter, prefer only favors. Also include_answer, include_raw_content, chunks_per_source. auto_parameters may switch to advanced and cost more.
  • Tavily Extract / Map / Crawl: Extract takes up to 20 URLs per request, 1 credit per 5 successful URLs (basic). Failures come back in failed_results even when HTTP is 200. Map: 1 credit per 10 pages. Crawl = Map cost + Extract cost. Best practice: Search first, then Extract only the chosen URLs, filter by score, track spend with include_usage.
  • MCP: a Host (the AI app) runs one Client per Server, 1:1. Messages are JSON-RPC 2.0. Transports: stdio for a local server run as a subprocess, Streamable HTTP for a remote server (OAuth recommended). Servers expose tools, resources and prompts.
  • MCP security: no token passthrough (a server must not accept tokens not issued for it). Watch for the confused deputy and SSRF. A session ID is not authentication. Least privilege, widened gradually.
  • Error recovery: retry, return the error to the model so it can correct itself, fallback, stop after N failures.
  • Evaluation: a test set (golden data), LLM-as-a-judge, groundedness, task success.
  • Guardrails: input and output filtering, human approval for sensitive actions, a token budget per run, and treating web content as data, not instructions (prompt injection).
Sources: Structured output, Function calling, Tavily Search, Tavily credits, MCP architecture, MCP security

3. Customizing a model with your own data

~20%
ApproachUse whenNot for
PromptingAlways the starting point. Cheap and fast.Behavior you cannot stabilize with a prompt
RAGFresh, private or changing knowledge; citing sourcesChanging style or format
Fine-tuningFixed format, style, a narrow task, shortening a long promptFacts that change
  • LoRA: small adapters, cheap and fast, little data. Full SFT: all weights, expensive, maximum quality. Distillation: a large teacher teaches a small student, close quality at lower cost.
  • Flow: client.files.create(purpose="fine-tune"), then client.fine_tuning.jobs.create(...), then poll the status. Hold out 10-20% of examples for validation.
  • Hyperparameters: n_epochs, learning_rate, batch_size, lora, lora_r, lora_alpha, lora_dropout, packing, context_length (default 8192).
  • packing=false with a context_length far larger than your examples means heavy padding and wasted compute.
  • Dataset formats: JSONL in four types: conversational (last message must be from the assistant), instruction (prompt/completion), text, and pretokenized (label -100 masks tokens from the loss). Up to 50GB via Data Lab, 20GB via the Files API.
  • Job lifecycle: terminal states are succeeded, failed, cancelled. On failure, job.error has code, message and param. Transient 5xx errors are safe to retry. checkpoints.list returns checkpoints; deploying the latest is recommended.
  • Models: context from 8192 to 131072. Some models allow full fine-tuning only (DeepSeek, Gemma 4), others LoRA and full (gpt-oss). A LoRA adapter on an MoE model must be merged before deploying to a Dedicated endpoint.
  • Data Lab: inference logs (not collected when ZDR is on), datasets prepared with SQL, uploaded or connected from S3, batch and fine-tuning outputs, and distillation pipelines. Raw completions are auto-deleted after one year; datasets stay until you delete them.
  • Distillation in the cookbook: a large teacher (Qwen3-235B) generates data in batch, then a LoRA on a smaller student (Qwen3-30B-A3B).
  • Train loss down and validation loss up = overfitting: fewer epochs, more data, lower learning rate.
Sources: Supervised fine-tuning, Datasets, Models, Data Lab

4. Production AI Operations

~25%
  • HTTP 429: exponential backoff with jitter, honor Retry-After. Never retry immediately in a loop.
  • Dynamic rate limits: evaluated in 15-minute windows. Average usage at 80% or more of the limit raises it 1.2x; 50% or less lowers it 1.5x. Ceiling: 20x the base. Headers: x-ratelimit-remaining-*, x-ratelimit-reset-*, Retry-After. x-ratelimit-over-limit: yes means the request was served at lower priority, an early warning.
  • API keys: shown only once at creation. Nebius can auto-revoke a leaked key. A Project Admin can create and delete any key, a Member only their own. Keep keys in env vars or a secret manager, one key per environment.
  • ZDR (Zero Data Retention): set at the organization level, applies to all projects, only an Org Admin can change it. Without ZDR, inputs and outputs are stored in Finland for speculative decoding only, never for training. With ZDR nothing is stored.
  • Serverless vs Dedicated: Serverless = per token, shared, rate-limited, region "Global". Dedicated = per GPU-hour (per-minute granularity), a fixed region you choose, min/max replicas, no standard rate limits, custom weights. You pay only while at least one replica is ready. Stopping releases the capacity.
  • Prompt caching: implicit and best-effort, no opt-in, no TTL setting. Put static content (system prompt, tool definitions) first. Measured in usage.prompt_tokens_details.cached_tokens (with streaming you need stream_options.include_usage). Cached pricing applies on Serverless only, not to Batch.
  • Residency: public endpoints are "Global" and may change region. Only Dedicated is contractually region-pinned. Fine-tuning data is stored in the EU and you cannot choose the region. Certifications: GDPR, ISO 27001, ISO 27701, SOC 2 Type II, HIPAA, EU-US DPF.
  • Cost: smaller model, Base instead of Fast when latency is not critical, shorter prompts, caching, Batch for non-urgent work, capped max_tokens.
Sources: Rate limits, Dedicated endpoints, Cached tokens, Legal quick guide. Not documented: a formal key-rotation procedure.
